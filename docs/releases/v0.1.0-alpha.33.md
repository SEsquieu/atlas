# Alpha.33: experimental replaceable orchestration bridge

Status: signed test APK delivered; phone acceptance pending. First milestone slice merged in [PR #66](https://github.com/SEsquieu/atlas/pull/66); [major milestone #65](https://github.com/SEsquieu/atlas/issues/65) remains open. Native execution is the default.

## What changes

- Portable core source in `packages/atlas-runtime-core`, with a reproducibly generated bundled artifact.
- Application-owned, service-retained isolated JavaScript engine. No per-token, speech-chunk or UI-event IPC.
- Signed external bundle import through native settings; immutable content identity and per-task version pins.
- Strict bounded manifest/command fields, pre-parse JSON nesting limits, heap/deadline limits and cancellation cleanup.
- Existing tasks retain their runtime when defaults change; legacy tasks remain native. Corrupt default selection preserves recovery controls without altering pinned tasks.
- Empty-slice yields cannot form a busy loop. Host leases, durable receipts, permission gates and tool execution remain authoritative.

The replaceable surface currently supplies additional guidance and infer/yield decisions. Context projection, model response handling and recovery still contain Kotlin orchestration. There is no issue/PR service or automatic update feed. This release does not complete the major milestone or enable unrestricted self-modification.

## Phone test cycle

1. Start in Native mode. Keep ChatGPT reasoning at Medium and use the existing MazeGen app. Ask: “Make the existing MazeGen app more robust. Use your judgment to choose the most worthwhile improvements, implement them, test them, and make the updated app live.”
2. In Data & activity, select Bundled core. Start a fresh task/session and use the same broad goal, followed by “Keep improving it. Decide what would make the biggest difference next.” This checks interaction and continuation; different workspace states and model outputs prevent a clean performance comparison from one pair alone.
3. During an active task or user-input wait, switch the default back to Native. The current task must retain its core ID, keep its input/approval flow and avoid repeated effects. New tasks use Native. Check pause/resume and typing while work is blocked.
4. Export the whole session. Evaluate decision overhead separately from provider latency, tool/test time, source rewrites and token use. Record text/voice responsiveness and any stalls.

Signed bundle import is available for development testing. Supply a publisher public key independently, import a signed JSON bundle and review the native activation prompt. Bad signatures, incompatible bridges and malformed bundles must leave the selection unchanged. Existing tasks stay pinned after activation. An unavailable/broken pinned core requires cancelling that task and starting a new one; selecting Native alone does not migrate the task.
