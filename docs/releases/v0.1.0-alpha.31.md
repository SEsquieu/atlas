## Fixed phone test cycle

Use the same model/provider settings for comparable runs and export the resulting session logs. Record candidate and build identities so results cannot be mixed across versions.

1. Repair MazeGen in its existing workspace. Generate a seeded maze, independently assert start-to-exit route behavior, test Reset/Solve, and activate. Revisit the other existing workspaces.
2. During a native approval or clarification blocker, type a response without pausing the session. Confirm the original task resumes and a delivered candidate has no obsolete blocker.
3. Exercise manual testing of a behavior the harness cannot independently verify. Confirm the native prompt identifies the candidate and outstanding criteria, then approve. The receipt must say unverified/tested=false. A changed user instruction must require fresh confirmation.
4. Inspect deliberate zero/nonzero count failures. Compare explicit expected and actual counts with the visible app; require honest failure reporting.

From each fixed task report first-attempt valid tool arguments, total tool calls, model steps, cumulative input/output tokens, and active elapsed milliseconds. Cumulative input counts repeated prompt tokens, not unique content or billed cost. Compare against the alpha.30 baseline only for matching tasks. Packet reduction unit tests are deterministic evidence of reduced duplicate transmission, not a live-model speed benchmark. Keep #53 open until that comparison exists.
