# Atlas alpha.20 — task outcomes and rendering evidence

Candidate staging/test/validation failures can be superseded by a later durable activation receipt for the same workspace and base, provided that receipt's revision is still live. Original calls remain failed in the audit; the task checkpoint records the resolving operation and timestamps. Unknown operation outcomes and unrelated workspace failures remain blockers. A completed fixture tool with `passed:false` now counts as failure. Tool ordering is stable when proposals share a creation timestamp.

Package activation receipts and pure fixture reports now appear in the turn status projection. Historical slice cards show their start/end times and identify themselves as slice history rather than the current task state. Normal yields direct the operator to current task status. Task cards distinguish current blockers from superseded candidate errors.

Structural validation no longer says activation is unavailable. Validation and fixture receipts report whether activation was performed and the concrete next step. Core capability, a passing fixture check, and activation remain distinct facts.

Web diagnostics sample actual HTML/body backgrounds, viewport/element geometry, stylesheet availability and renderer readiness. The fixed host probe executes no agent-supplied diagnostic code. Resource request traces, Android API and WebView provider/version are included. Probes have a timeout and revision/surface replacement checks. Source CSS is intended appearance, not pixel evidence.

The native WebView canvas defaults to Atlas dark while loading or when the document is transparent. Authored opaque backgrounds retain control, including light themes. This prevents white native-canvas bleed-through; it does not establish the cause of every gradient/compositor issue. The phone screenshot matched the live revision and showed styled cards on a white canvas. The original source paints correctly in a direct Android 15 WebView; actual Compose-panel tests and Android 16 coverage distinguish embedding/provider differences. Regression pixels must match a painted green gradient, not simply a dark native fallback.

Session ZIP exports include an index and up to eight available workspace viewport images (8 MiB image budget), newest first. Missing/limited images are explicitly marked, and up to 64 capture metadata entries are indexed. Physical camera images are excluded. Main-process exit history is separated from worker cleanup history; Android's retained history remains limited.

Oversized whole turns containing large tool payloads can now be checkpointed using bounded previews plus original-message IDs and hashes. Dialogue remains intact, source/audit payloads remain durable, and only fully represented turns advance the checkpoint. An oversized dialogue still fails safely rather than silently skipping history.

Acceptance: Secure unit/lint checks, renderer/storage/activation/containment device tests on Android 15 and 16, signing verification, and then phone confirmation of the white-canvas symptom. Real-device diagnostics remain necessary if the provider-specific symptom persists.
