# Atlas alpha.18 — local application packages

Atlas can author local HTML/CSS/JavaScript applications, call packaged pure exports as reusable tools, test them in isolated workers, and activate immutable revisions without rebuilding Android. New authoring uses one package contract. Historical native workspaces remain readable and loadable; their authoring tools are no longer in the production agent catalog.

The host owns workspace-scoped records, transactions, retry receipts, version fences, package revisions, startup checks and recovery. A hot swap replaces the visible surface and rehydrates from records. Unsaved JavaScript heap/UI state is not transferred automatically. Closing a workspace disposes its foreground resources. Failed startup preserves the previous revision; a failure in an active surface stops its epoch and offers retry without deleting records.

Presentation runs in an opaque-origin browser sandbox with packaged-only resources and a main-frame/epoch-bound bridge. Network, device, credentials and persistent background services are not available in this release. Packages requesting them receive explicit unsupported-capability errors; no package can grant itself permission. Schema-version migrations and nonempty native-workspace conversion are also explicit blockers.

Export/import preserves package source, records and logical record references. Imported packages receive a new workspace identity and start stopped, with no grants or live handles.

## Validation and delivery

Secure unit tests and lint plus the Android 15 emulator suite must pass before signing. Device checks exercise the real worker process, runaway termination, large package transport, hostile child-frame network probes, scoped storage retries and the production agent create/stage/test/activate/edit path. These are bounded checks for the tested Android/WebView configuration; phone usability and endurance are the next alpha checks.

`apps/atlas-android/RELEASE` is metadata only. A post-validation change there triggers the existing Secure packaging workflow without repeating device tests for unchanged application bytes. Every functional Android change still triggers the device workflow. Routine delivery remains one signed Secure APK; LAN and DEV are opt-in diagnostic builds.

## Phone check

1. Ask Atlas to build a small expense tracker or single-player game as a new workspace. It should use package tools without asking for a new Android primitive.
2. Use it, save several records, then ask for a layout/behavior change. The revision should reload in place and retain records.
3. Switch between Session and Workspaces, pause/resume the session, and reopen the workspace. Shared PTT/input stays anchored; foreground app resources stop when its panel closes.
4. Export/import the workspace. Verify linked records and the explicit retry/open step on the imported copy.
5. For failures, export the session/workspace logs. Atlas can inspect saved checks, source, visible console diagnostics and workspace-only screenshots.
