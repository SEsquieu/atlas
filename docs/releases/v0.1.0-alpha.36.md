# Alpha.36: autonomous device-aware workspace visual testing

Implementation merged in [PR #76](https://github.com/SEsquieu/atlas/pull/76). Physical-device qualification remains open under [#75](https://github.com/SEsquieu/atlas/issues/75) / AF-019.

## Behavior

Atlas can render an immutable staged candidate, inspect layout, capture real pixels and exercise controls while the user stays in Session. `workspace_visual_status` discovers the optional facility; `workspace_visual_test` supplies open, inspect, capture, interact, finish and close. The model chooses testing by need; no universal visual activation gate is added.

The host uses an app-private virtual display and attached hardware-accelerated Presentation in a separate service process/WebView profile. Production package/security contracts, shared native chrome, disposable SQLite and simulated BLE are reused. Chromium visual state and hardware frame commits precede PixelCopy. A trusted color calibration must pass on the target device; there is no software-draw fallback.

Viewport dimensions come from the actual Session/Workspace content bounds after Atlas controls, navigation, system UI and keyboard layout, followed by shared workspace chrome. Profiles expose display-mode dimensions, density, font scale, orientation, insets, touch support and measured JS viewport/DPR. Explicit alternatives support responsive probes; apps should not embed the current phone dimensions.

Native taps/swipes hit only the test WebView. Text, keys and DOM actions are fixed synthetic inputs. Geometry reports bounded visibility, clipping, overflow and center-point occlusion facts; the agent judges design. Mock BLE never gains real radio/OS permission or live grants, and test storage cannot change active records.

Task-owned handles preserve state across slices. Cancellation, Activity/session/task stop, timeout, crash and expiry release resources. Process death expires DOM state rather than replaying gestures. Limits: one instance, 4 million display pixels, 4096 pixels per axis, 128 operations, 5 minutes idle and 20 minutes absolute lifetime; remote timers/surface pause after 30 seconds idle. Atlas must stay visible and unlocked.

Optional finish receipts require assertions, no recorded errors and a screenshot after the latest interaction batch. Evidence is bound to candidate hash, base revision and data version, and matching evidence accompanies activation. Existing pure/startup/BLE/persistence/permission gates remain intact. Full geometry stays durable; finish/activation return compact summaries.

See [the complete contract, limits, Android sources and real-device plan](../workspace-visual-testing.md).

## Phone cycle

Stay in Session and start a fresh task:

> Build me a Snake game, make sure it looks good and works on my phone, and let me know when it's ready. Keep me in this session while you develop it. Choose the checks you need and fix any problems you find.

Then:

> Use your judgment to make it more robust and easier to use. Preserve saved scores and verify the changes that need checking.

Check that testing does not open intermediate workspaces, steal focus or disturb typing. Compare the delivered app with isolated captures; exercise canvas controls, orientation, font/display scaling, keyboard states, save/reload, cancellation, idle resume and process death. Record WebView/OneUI/device profile, operation timing, memory, thermal/battery impact and resource counts over repeated cycles, then export the session.

Per-open calibration and emulator checks do not establish Samsung compositor reliability, live-model convergence, sustained leak-free endurance, latency reduction, battery impact or physical peripheral interoperability. The separate #65 runtime/automation migration remains open. This host build does not select a runtime proposal or change existing task pins.
