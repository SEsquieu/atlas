# Atlas alpha.19 — workspace recovery diagnostics

Delete is available on active and archived workspaces and in the open workspace header. Every path requires a confirmation dialog. Confirming closes the panel and atomically deletes records, revisions, candidates, checks, operations and lifecycle state, clears linked sessions, and advances their navigation fences. Existing session audit history is retained. Cancel changes nothing.

Workspace library/revision polling runs on IO instead of making repeated database reads during Compose rendering. This removes one concrete UI blocking path; it is not a proven root cause for the alpha.18 phone lockup.

Session exports include `runtime-diagnostics.json`: up to eight recent process-wide stall/exception samples plus Android's last five available process-exit reasons. A separate recorder captures the main thread stack after five seconds without a main-loop acknowledgement. Samples are bounded, independent of SQLite, and do not terminate or restart the app. Fatal exception handling delegates to Android. Earlier lockups cannot be reconstructed retrospectively from missing stacks.

Draft render diagnostics return an explicit no-surface status. Web diagnostics report viewport availability; captured console evidence now includes unhandled JavaScript errors and promise rejections. Failed pure fixtures include bounded worker error details. Activation receipts explicitly limit their proof to pure fixtures and startup readiness.

The authoring contract now documents the one-JSON-input export convention, matching browser call sites, and exact create/update/delete storage shapes. These changes do not repair previously generated packages automatically. In the Neon Vale log, changing `transition` to accept one object without updating its UI caller broke interactions; update mutations also used incorrect field names. Repair those sources before retesting the existing app. Pure fixtures and startup readiness are not proof of UI save/resume behavior.

Validation: Secure unit/lint and Android device workflow are required before delivery. The device suite exercises console error capture in addition to the existing runtime, containment, storage and activation flows. Phone lockup reproduction and endurance testing remain necessary.
