# Atlas 0.1.0-alpha.29

Release preparation; installable build and phone qualification are recorded separately after CI.

## Changes

- Recover unambiguous misplaced source entries without regenerating an app; conflicting entries remain rejected.
- Prevent unnecessary failed visual handoffs from blocking committed delivery. Required checks and uncertain effects remain blocking.
- Bound repeated identical deterministic proposals across continuation slices; corrected arguments and transient retries remain distinct.
- Distinguish physical camera evidence from workspace viewport screenshots.
- Allow native-confirmed acceptance of exact candidate behavior for manual testing. Host-authored prompts show the app and unverified criteria. Acceptance is durable, candidate-bound, and never labeled a test pass; permission and host integrity gates remain unchanged.
- Add SVG click support, bounded synthetic DOM pointer drag/cancellation with test-only simulated capture, exact-text and attribute assertions, criterion-level evidence and failure classification. Author-written tests do not independently prove semantic correctness.

## Phone acceptance

1. Fresh app creation: one workspace, no malformed-call loops, clean terminal task completion.
2. Save a distinctive user record, leave/reopen, then request a favorites edit; verify records survive the revision.
3. Request draggable graph points. Verify dragging and displayed coordinates; ask to activate an unverified change for manual testing if a behavior cannot be exercised.
4. Confirm that native acceptance names the app and exact uncertainty. Decline once, then explicitly approve a new proposal. Changed candidate bytes need new approval.
5. Unavailable optional screenshots must not leave a successfully delivered app waiting. Camera pixels must never be described as workspace pixels.
6. Export logs and compare malformed attempts, repeated failures, elapsed time, token usage and final task state with the alpha.28 baseline.

Existing alpha.28 workspaces are not automatically rewritten. Secure is the standard APK; LAN/DEV are separate opt-ins. Install over the same flavor using the persistent signing identity, without clearing data. The source alpha name alone does not prove that a signed artifact exists or completed live acceptance.
